## Shared operation and response contract

- `EDITOR_MCP_OPERATION_REGISTRY` is exhaustive over `EditorMcpCommand`; it supplies the public tool name, native input validator, domain, mutation category, revision policy, workspace/build requirement, handler path, result shape, description and annotations.
- MCP capability reporting serializes this registry. The authenticated native bridge validates inputs through the registry and derives revision requirements from the same definitions.
- Success and failure responses use envelope version 1 with a request ID, before/after host-project identity and document revisions (`documentRevisions`), affected/created IDs, warnings/normalization, save state, and a structured error code when unsuccessful. Existing result fields remain flattened alongside the `result` payload for client compatibility.
- Rendering-dependent operations do not silently switch workspaces. Their workspace/build requirements are advertised by the registry and checked by the Editor handler.

## Explicit exclusions and constraints

- Cosmetic menu opening, divider dragging and OS clipboard access are not separate tools; semantic ID-based editing and structured payloads are provided instead.
- Timeline preview/audio decoding/import preview require the Timeline workspace; camera evaluation/framing require Camera; interaction tests require the interaction renderer; waveform profiling requires a profile-enabled development build.
- Camera and sequence replacement use strict complete typed snapshots where the underlying Editor currently has no stable semantic command API. Locked entities, references, IDs and paths are validated at the native boundary.
